# Aura visual system

Status: **proposed visual checkpoint, awaiting owner review**. This is the current direction for the production website and desktop app. The checkpoint establishes a representative homepage and desktop workspace in both appearances. Full surface rollout, visual approval, native release verification and integration acceptance remain pending. Do not describe this styling as approved until the owner reviews the checkpoint. These decisions supersede the old dark-only Graphite, Orbit and Shallows directions. Historical Design Lab screens are studies, not product authority.

## Purpose and boundaries

The website combines Vercel's restrained hierarchy, Harvey's clear organization, and Typesafe's distinctive staged product proof. The desktop takes its organizational and visual cues primarily from Devin, with restrained touches from the Aura website. Adapt patterns to auracode's own product and capabilities. Do not copy reference brands, artwork or content, or imply unsupported functionality. Recompose layouts and navigation grouping while preserving existing actions, content, capabilities and workflows. Preserve the actual auracode logo, including its sea lion and turtle artwork, and its app icons and favicons. Remove independent decorative animals, swimming and water motifs across production surfaces and generated social art.

## Shared foundation

`packages/ui/src/graphite/tokens.css` is the shared token source; `graphite/tokens.ts` and its tests mirror palettes where code needs them. Existing `--g-*` names are compatibility names for the Aura foundation, not permission to restore the former Graphite direction. Keep color, typography, spacing, radii, motion, states, code and terminal values semantic and centrally defined. Product-specific layout and density belong near each application. Do not introduce a parallel uncoordinated token system. The sparse shared accent currently uses `--g-volt`: dark `#ccff33`, light `#496800`. Reserve it for small meaningful accents, keeping success, warning and danger distinct. Verify solid text contrast on its actual surface.

Dark background and first four surfaces are `#101112`, `#141516`, `#1c1d1f`, `#202226`, `#292b2f`; light counterparts are `#fafafa`, `#ffffff`, `#f4f4f5`, `#f0f0f2`, `#e8e8eb`. Lines, text, focus, syntax, ANSI, selection and status tokens have explicit values for both modes in the token source. Preserve theme pairs and mirror tests when changing them. Do not assume a dark code or terminal surface in light mode.

Desktop uses Inter for interface and prose, website uses Geist, and machine-generated text uses Geist Mono. Desktop chrome is 13/20px, prose 15/24px, metadata 12/16px, title 20/28px. Website hero is 48/52px, 36/40px on mobile; section heading 32/38px; body 16/24px. Use a compact 6, 8 and 12px radius family. These values guide production consistency; preserve legibility and actual content needs.

Appearance defaults to System, with persisted Light and Dark overrides. Desktop preference is profile-local in the versioned setup preferences; website preference is local to the browser. Follow OS changes while System is selected. Keep document root, native window and menus, portals, terminal palette, forms and third-party verification consistent with the resolved appearance. Initialize before visible content where feasible, respect storage failure and non-JavaScript fallbacks, and preserve the website's hashed content security policy.

## Desktop composition

Design for a 1440 x 900 native window, minimum 960 x 640, with 52px clearance for native title controls. A manually collapsible sidebar is 256px expanded and 56px as a rail. At 1200px and wider, the existing Changes panel can resize from 320 to 560px; below that it overlays at up to 420px. The existing terminal remains persistent and resizable. These are layout targets, not new capabilities. Account for long titles, narrow windows, platform title controls, keyboard and focus order, scrolling and no horizontal overflow.

Cover setup and agent discovery, workspace and empty chat, populated and streaming transcripts, picker and composer, permissions and questions, queued messages, error and recovery states, project and worktree management, Git and changes, terminal, plugin library, settings and account/sync, and all menus and dialogs. Settings currently includes General, Instructions, Account, Configuration sync, Shortcuts and About, and entry points to Agents and Plugin library. Rearrangement must retain every capability and accessible route. Preserve underlying Tauri commands, data, keyboard behavior, native focus and ongoing processes when restyling.

## Website composition

The homepage starts with three sparse objects: a headline and Download action, a crop of the real desktop agent selector, and a concise three-line fact proposition. Show the full real desktop capture 32px below. Follow with a six-tab capabilities section, Harvey-like in organization with the control list taking one third and proof taking two thirds. Typesafe-inspired handoff proof stages two successive real chat states from upper left to lower right with one causal hairline; they are a sequence, not parallel agents or invented functionality. Finish with FAQ, closing action and footer. Avoid unsupported claims or repeated proof. Use a maximum content width of 1200px, 32px desktop and 20px mobile gutters, and 96px desktop and 64px mobile section spacing.

Preserve all content and actions on home, download, sign in, sign up, device verification, account, privacy, terms, changelog and error pages. Keep download and essential information usable without JavaScript. Product images must come from actual desktop preview states, using `apps/web/scripts/product-images.mjs`, and reflect the integrated desktop in each theme. Do not present fabricated screenshots as product evidence.

## Motion and accessibility

Motion is event-driven, never ambient. Use `cubic-bezier(0.2, 0, 0, 1)`: hover 120ms, press 80ms, popover 160ms with at most 2px travel, panel 180ms, website entrance 240ms with at most 8px travel once per capability, and fixed-width agent-name rotation 250ms. Reduced motion removes movement and duration. State changes must remain understandable without animation. Preserve visible keyboard focus, native dialog behavior, accessible names, error announcements, readable contrast, and robust zoom and reflow.

## Governance and verification

For future visual work, read this document and [reference-audit.md](reference-audit.md), inspect shared tokens and production components, then compare against the approved checkpoint artifacts once they exist. Do not use a historical lab screen as a golden reference. During the checkpoint, visual artifacts are proposals; record the owner's approval and artifact locations before treating them as golden. For a new feature, extend semantic tokens and interaction patterns, show every state in light and dark, and preserve accessibility and behavior. Update this document when an owner decision changes the design; do not leave competing active directions in plans or READMEs.

Run `pnpm check` and `pnpm build`, `pnpm --filter @auracode/web test:browser`, and desktop `check:chat`, `check:setup`, `check:settings` and `node apps/desktop/scripts/check-layout.mjs` as appropriate to changed surfaces. Verify both themes, system switching, saved preferences, portal and terminal updates, keyboard, reduced motion, responsive sizes and contrast. Browser fixtures and screenshots do not establish native macOS/Windows release acceptance; verify native materials, menus and title controls on supported platforms separately. Existing style checks enforce token usage; use objective checks for meaningful invariants rather than freezing arbitrary layouts.
