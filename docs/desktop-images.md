# Chat image previews

Image attachments appear as removable thumbnails inside the existing composer. Sent and saved user messages resolve their original prompt image parts by turn, queued prompt or steering message. A thumbnail opens the standard image dialog; Escape closes it and returns focus to its trigger. Missing files show an unavailable tile, and the dialog offers Retry. Text attachments, mentions, drafts, keyboard sending, model controls and dictation retain their existing behavior.

Agent Markdown images use local paths within the chat folder. The parser accepts relative paths, `./` paths, percent-encoded spaces and local file URLs, but does not fetch remote URLs or execute active image formats. The native reader opens each component without following symlinks or Windows junctions and reads through the checked file handle. Credential paths and `.git` remain unavailable. Local files must be regular files no larger than 12 MiB.

Native ACP, Claude Code, Codex and Pi responses also pass through an image adapter before protocol mapping. Known image content blocks, embedded image resources and image data URLs are normalized into private profile attachments. Codex's `imageView.path` and `imageGeneration.savedPath` remain available when no binary payload is supplied; generation payloads are stored when available, including when the native saved path is outside the chat. A response carries at most eight stored images and 16 MiB of encoded input. Unsupported, malformed or oversized image payloads become explicit unavailable metadata. The adapter retains its pending read across driver select loops so stop commands remain responsive while storage runs.

The stored reference is `aura-image:<64 lowercase hex SHA-256>`. It identifies normalized PNG bytes, and the preview API requires a matching `composer_attachments` row for the requested chat. Knowing another chat's hash does not grant access. This stable reference survives ownership metadata being copied with new IDs. Image bytes are absent from transcript events and tool raw inputs; protocol log redaction is documented separately in [protocol-image-logging.md](protocol-image-logging.md).

Decoding runs off the asynchronous runtime with a shared two-operation limit. Thumbnails fit within 320 pixels and 512 KiB; enlarged previews fit within 2048 pixels and 4 MiB. Both are re-encoded PNGs without source metadata. The renderer keeps at most 48 idle thumbnail URLs per mounted chat, releases dialog images on close, and revokes all URLs on chat unmount. Late responses cannot revive a cleared cache. Each answer previews up to eight distinct image references, using the existing incremental Markdown block cache while streaming.

## Verification

`node apps/desktop/scripts/check-images.mjs` drives the production components through an owned in-memory fixture in Chromium and WebKit, both appearances and narrow windows. It covers drafts, remove/reattach, sent and reopened history, agent local images, missing paths, keyboard dialogs, read failure and retry, accessibility and the absence of remote image requests. This is browser evidence, separate from native verification.

Rust tests cover bounded normalization, damaged formats, regular-file confinement, Windows junction rejection, chat ownership, saved-image reopen, native image payload scrubbing, storage timeout and cancellation. Conversation tests cover ownership-preserving image retention. The integrated native smoke additionally exercises the real paste/import/preview IPC, sends an image and checks the reopened gallery.
