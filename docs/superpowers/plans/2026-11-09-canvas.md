# Canvas: draw it, say it, send it

Owner, 8 November 2026: "canvas mode ... a custom version of something like microsoft paint ...
a canvas which opens up and u can draw out flows, ideas, everything, and then include the canvas
in the prompt and it takes it in with the context u give it in the prompt, and an additional
feature is like activate voice mode while ur drawing and it somehow all links together."

## Decisions

1. **auracode's own drawing surface, not a library.** A whiteboard library brings its own visual
   direction, which the visual language rules out, and the owner asked for a custom one. The
   canvas is SVG drawn from a small vector model (strokes, shapes, arrows, text) in the theme's
   tokens, so it repaints with the theme and appearance like everything else.
2. **It opens in the chat, above a live composer.** Canvas, beside Attach in the composer, puts the
   canvas in the transcript's place; the composer stays below it, so the person types the context
   (or dictates it) while the drawing is in view. Close canvas brings the transcript back and keeps
   the drawing. A dialog would make the composer inert, and a side panel is too narrow to draw in.
3. **Add to message is explicit.** It renders the drawing to a PNG cropped to what was drawn, adds it
   as the composer's image attachment (replacing the canvas image added before), and puts the
   drawing's outline and the narration in the draft, where the person can edit them before Send.
   What is sent is always what the composer shows.
4. **The outline makes a drawing readable without vision.** Labelled shapes, the arrows between them
   (A → B by the shapes they start and end on), and free text, as a short list. An agent without
   image support still gets the outline; the image is left out and the canvas says so.
5. **Talking while drawing links the words to the strokes.** Talk in the canvas toolbar starts
   dictation for the canvas (the composer's own dictation stays the composer's). Each phrase that
   settles takes the shapes drawn while it was spoken: the canvas numbers them on the drawing with a
   small marker, and the narration reads "1. this is the API gateway", so the image and the words
   point at each other. Nothing is sent until Add to message and Send.
6. **The drawing stays with the chat on this device** (local storage per chat), so a canvas can be
   revised and sent again. Clear empties it, with Undo.

## Tools

Select (V), Pen (P), Highlighter (H), Rectangle (R), Ellipse (O), Arrow (A), Text (T) and Eraser
(E); seven colours from the theme (ink and the terminal palette's red, yellow, green, blue,
magenta and cyan), three widths, Undo (Ctrl+Z) and Redo (Ctrl+Shift+Z, Ctrl+Y), Delete for the
selection, arrows to nudge it, Space or the middle button to pan, Ctrl+wheel and the zoom buttons
to zoom, and Fit. Shift keeps a square, a circle or a straight line. An arrow that starts or ends
on a shape follows it when the shape moves. The pen takes a stylus's pressure.

## Edge cases

- A huge drawing: the export is at most 2048 px on its longer side (the composer's limit) and the
  saved drawing at most 2 MB; past that the canvas says it cannot keep more.
- Nothing drawn: Add to message is unavailable, and says why.
- The composer's attachments are full (8): Add to message says so and adds only the outline.
- The agent does not take images: the outline and narration go in, the image does not, and the
  canvas says so.
- Dictation fails, is cancelled or the microphone is missing: the canvas says so in its own bar;
  the drawing is untouched.
- Theme or appearance change: colours are token names, so the drawing repaints; the export uses the
  colours in effect.
- Keyboard: every tool is reachable from the toolbar by Tab and arrows, the shortcuts work while
  the canvas has focus (never while typing in its text box or the composer), and the drawing
  surface names its contents for a screen reader with the outline.
- Terminal chats have no composer, so no canvas.
- Reduced motion: no transitions; the canvas opens in place.

## Order of work

1. The vector model, its history (undo and redo), hit testing, the outline and the narration
   grouping, with unit tests.
2. The canvas surface and toolbar, and the composer's Canvas button.
3. Export and Add to message through the composer's existing paste path.
4. Talk: dictation for the canvas and the numbered markers.
5. The browser fixture (`?preview=canvas`) and its check in the fixture suite, both engines and
   appearances, with axe; the layout check's modes.
